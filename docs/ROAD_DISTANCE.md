# 자동차 도로거리 모드 설정

기본 프로그램은 **직선거리**로 방문순서를 추천합니다. 서버도 설치도 필요 없습니다.
여기에 작은 길찾기 서버를 붙이면 **카카오모빌리티가 알려 준 실제 주행거리**로
방문순서를 추천하고 예상 운전시간까지 보여 줄 수 있습니다.

> **서버는 선택사항입니다.** 서버가 없어도 프로그램은 지금까지처럼 완전히 동작하며,
> 화면에서 도로거리 버튼만 비활성화됩니다.

설계 제약은 [AGENTS.md](../AGENTS.md), 사용법은 [README.md](../README.md),
화면 규칙은 [UI_GUIDE.md](UI_GUIDE.md)를 보세요.

---

## 1. 왜 서버가 필요한가

| | 쓰는 키 | 어디서 호출 |
|---|---|---|
| 장소 검색 (기존) | **JavaScript 키** | 브라우저에서 직접 |
| 길찾기 (새 기능) | **REST API 키** | **서버에서만** |

카카오모빌리티 길찾기 API는 REST API 키를 요구합니다.
REST 키는 JavaScript 키와 달리 **도메인 제한으로 보호되지 않아**,
HTML에 넣으면 소스 보기만으로 그대로 유출됩니다.
그래서 키를 다루는 최소한의 중계 서버를 따로 둡니다.

브라우저는 좌표만 보내고 거리표만 돌려받습니다. **키는 브라우저로 내려가지 않습니다.**

---

## 2. 빠른 시작

Node.js 18 이상이 필요합니다. **설치할 패키지는 없습니다** (의존성 0개).

```bash
KAKAO_REST_API_KEY=여기에_REST_키 node server/server.mjs
```

```
http://localhost:8787
```

위 주소로 접속하면 프로그램이 열리고, 화면 아래 **계산 기준**에
`자동차 도로거리`가 자동으로 선택됩니다.

서버가 화면까지 같이 서빙하므로 이 경우 설정에서 **서버 주소를 넣을 필요가 없습니다.**

### REST API 키 받기

1. <https://developers.kakao.com> → 내 애플리케이션 → 앱 선택 → **앱 키**
2. **REST API 키**를 복사합니다 (JavaScript 키가 아닙니다)
3. 카카오모빌리티 **길찾기 API 이용 권한**이 필요합니다.
   권한이 없으면 서버가 `KEY_FORBIDDEN` 으로 안내합니다.
   신청은 <https://developers.kakaomobility.com> 에서 합니다.

## 3. 환경변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `KAKAO_REST_API_KEY` | (없음) | **필수.** 없으면 도로거리 모드가 꺼집니다 |
| `PORT` | `8787` | 서버 포트 |
| `KAKAO_PRIORITY` | `DISTANCE` | `DISTANCE`(최단거리) 또는 `TIME`(최단시간) |
| `KAKAO_RADIUS` | `10000` | 일괄 조회 반경(m). **API 상한이 10000이라 그 이상은 무시됩니다** |
| `MAX_POINTS` | `9` | 한 번에 계산할 지점 수 (출발지 1 + 출장지 8) |
| `RATE_LIMIT_PER_MIN` | `20` | IP당 분당 거리표 요청 수 |
| `DAILY_CALL_BUDGET` | `5000` | 이 서버가 하루에 쓸 카카오 호출 수 상한 |
| `UPSTREAM_TIMEOUT_MS` | `10000` | 카카오 응답 대기 시간 |
| `UPSTREAM_CONCURRENCY` | `4` | 카카오에 동시에 보내는 요청 수 |
| `ALLOWED_ORIGINS` | (없음) | 다른 주소에 올린 화면을 허용할 때. 쉼표로 구분 |
| `SERVE_STATIC` | `true` | `false` 면 API만 제공하고 화면은 서빙하지 않습니다 |

> `KAKAO_NAVI_BASE` 는 테스트에서 가짜 상위 서버를 끼우기 위한 값입니다. 운영에서는 설정하지 마세요.

## 4. 화면과 서버를 따로 두는 경우

GitHub Pages, ChatGPT Sites, 사내 게시판처럼 **화면은 정적으로 올리고**
서버만 따로 운영할 수 있습니다.

### 서버 쪽

화면이 올라간 주소를 `ALLOWED_ORIGINS` 에 넣습니다.

```bash
KAKAO_REST_API_KEY=여기에_REST_키 \
ALLOWED_ORIGINS=https://storm8787.github.io,https://내사이트.example.com \
SERVE_STATIC=false \
node server/server.mjs
```

`http://` 와 `https://`, 포트 유무까지 **글자 하나까지** 같아야 합니다.
목록에 없는 주소에서 오면 서버가 403으로 거절하고,
화면에는 "길찾기 서버가 이 주소의 요청을 거부했습니다" 라고 나옵니다.

### 화면 쪽

프로그램의 **설정 → 자동차 도로거리 → 길찾기 서버 주소** 에 서버 주소를 넣고
**연결 확인**을 누릅니다. 이 값은 그 브라우저에만 저장됩니다.

```
https://길찾기서버.example.com
```

### ChatGPT Sites 에 올릴 때

1. `출장방문순서추천.html` 파일 하나를 그대로 올립니다. 빌드할 것이 없습니다.
2. 이 상태로도 **직선거리 모드는 바로 동작합니다.**
3. 도로거리까지 쓰려면 위처럼 서버를 따로 띄우고
   `ALLOWED_ORIGINS` 에 ChatGPT Sites 가 준 주소를 넣은 뒤,
   설정에서 서버 주소를 입력하면 됩니다.
4. 서버는 **HTTPS** 로 공개해야 합니다. `https://` 페이지에서 `http://` 서버를
   부르면 브라우저가 막습니다.

> 서버를 인터넷에 공개하면 남이 내 카카오 호출량을 쓸 수 있습니다.
> `ALLOWED_ORIGINS`, `RATE_LIMIT_PER_MIN`, `DAILY_CALL_BUDGET` 을 꼭 설정하세요.

## 5. 구간 조회 방식과 그 한계

### 순서마다 부르지 않습니다

출장지 8곳이면 방문 순서는 40,320가지입니다. 순서마다 길찾기를 부르면 호출량이 폭발합니다.
그래서 **구간(방향별 거리)을 먼저 한 번씩만 조회하고**, 순서 비교는 브라우저에서 합니다.

지점 9개(출발지 1 + 출장지 8) → 방향별 구간 **72개**
(A→B 와 B→A 는 일방통행·중앙분리대 때문에 다를 수 있어 따로 셉니다).

### 2단계 조회

1. **다중 목적지 길찾기** `POST /v1/destinations/directions` — 출발점마다 1회.
   지점 9개면 **9회**로 대부분을 채웁니다.
2. **단건 길찾기** `GET /v1/directions` — 1단계에서 못 받은 구간만 1개씩.

### 반경 10 km 한계 — 반드시 알아 두세요

다중 목적지 API의 `radius` 는 **최대 10,000 m** 입니다.
그런데 충주시는 그보다 넓습니다. 예를 들어 충주시청에서 수안보면까지는 직선으로도 약 18 km라
**일괄 조회만으로는 덮을 수 없습니다.**

그래서 이렇게 처리합니다.

- 직선거리가 이미 반경을 넘는 구간은 **처음부터 일괄 조회에 넣지 않습니다.**
  (직선거리 ≤ 도로거리 이므로, 직선으로 10 km를 넘으면 도로로는 반드시 넘습니다.)
- 반경 안이어도 응답에서 빠진 구간이 있으면 **단건 조회로 보충합니다.**
- 두 단계를 거치고도 남은 구간은 `missing` 으로 보고하고,
  **결과를 만들지 않습니다.**

### 직선거리로 섞지 않습니다

도로거리를 못 구한 구간을 직선거리로 메우면 그것은 더 이상 도로거리가 아닙니다.
한 구간이라도 비면 계산을 멈추고, 어느 구간인지 알려 준 뒤
**직선거리 모드로 다시 계산하는 버튼**을 보여 줍니다.

## 6. 오류 안내

| 코드 | 화면 문구 | 원인 |
|---|---|---|
| `NO_SERVER` | 도로거리 계산 서버가 없습니다 | 서버 주소가 없거나 로컬 파일로 열었음 |
| `NO_KEY` | 서버에 카카오 REST API 키가 없습니다 | `KAKAO_REST_API_KEY` 미설정 |
| `KEY_INVALID` | 키가 거부되었습니다 | 키가 틀림 (상위 401) |
| `KEY_FORBIDDEN` | 이 키로는 길찾기 API를 쓸 수 없습니다 | 길찾기 이용 권한 없음 (상위 403) |
| `QUOTA` | 호출 한도를 넘었습니다 | 카카오 쿼터 초과 (상위 429) |
| `RATE_LIMIT` | 요청이 너무 잦습니다 | 이 서버의 분당 제한 |
| `DAILY_BUDGET` | 오늘 허용된 호출량을 모두 썼습니다 | 이 서버의 일일 상한 |
| `TIMEOUT` | 응답이 제때 오지 않았습니다 | 카카오 응답 지연 |
| `NETWORK` | 서버에 연결하지 못했습니다 | 서버가 꺼져 있거나 주소 오류 |
| `ORIGIN` | 이 주소의 요청을 거부했습니다 | `ALLOWED_ORIGINS` 누락 |
| `BAD_POINTS` | 좌표를 확인해 주세요 | 좌표 형식·범위·개수 오류 |
| `MISSING_LEGS` | 일부 구간의 도로 경로를 찾지 못했습니다 | 차로 갈 수 없는 구간 |

모든 경우에 **직선거리 모드로 다시 계산하는 버튼**이 함께 나옵니다.

## 7. 보안 점검표

- [ ] `KAKAO_REST_API_KEY` 를 **환경변수로만** 전달했는가 (코드·HTML·커밋에 없는가)
- [ ] 서버 로그에 키가 찍히지 않는가 *(서버가 로그 한 줄마다 키 포함 여부를 걸러냅니다)*
- [ ] `/api/health` 응답에 키가 없는가 *(존재 여부만 `road: true/false` 로 알려 줍니다)*
- [ ] 인터넷에 공개했다면 `ALLOWED_ORIGINS` 를 지정했는가
- [ ] `RATE_LIMIT_PER_MIN`, `DAILY_CALL_BUDGET` 이 적절한가
- [ ] 키가 유출된 것 같으면 카카오 개발자 사이트에서 **재발급**했는가

## 8. 검증 범위

```bash
node tests/road.mjs      # 도로거리 모드 (83건)
node tests/verify.mjs    # 직선거리 모드와 화면 전반 (122건)
```

`tests/road.mjs` 는 **가짜 상위 서버**를 띄우고 진짜 `server/server.mjs` 와
진짜 HTML을 Chromium으로 돌립니다. 검증하는 것:

- 방향별 비대칭 거리(A→B ≠ B→A)
- 전수 비교 결과를 **독립 Held-Karp 구현**과 교차검증 (복귀 포함/미포함, 출장지 8곳)
- **직선거리 최단 순서와 도로거리 최단 순서가 실제로 달라지는 사례**
- 반경 밖 구간이 단건 조회로 보충되는지
- 구간 경로 없음 / 키 오류 / 한도 초과 / 타임아웃을 구분해 안내하는지
- 서버가 없을 때 직선거리 모드로 동작하는지

> **실제 카카오모빌리티 API 는 호출하지 않습니다.**
> 운영에 올리기 전에 실제 REST 키로 공개 장소 좌표 몇 개를 넣어
> 한 번 확인하시기를 권합니다.

# UI 가이드

`출장방문순서추천.html` 한 파일의 화면 규칙입니다.
설계 제약과 보존 기능은 [AGENTS.md](../AGENTS.md), 사용법은 [README.md](../README.md)를 보세요.

> 이 프로젝트 규모에 맞게 **의도적으로 작게** 유지합니다.
> 컴포넌트 라이브러리나 대규모 디자인 시스템을 만들지 마세요.

---

## 1. 화면 구성

사용자가 해야 할 행동 순서대로 위에서 아래로 배치합니다.

```
헤더        프로그램명 · 한 줄 설명 · 상태 칩 · 설정 버튼
안내 상자    문제가 있을 때만 나타남 (정상이면 비어 있음)
[설정]      기본 접힘. 설정 버튼으로만 열림
1 어디에서 출발하나요?    출발지 — 미확정/확정 두 상태
2 어디를 방문하나요?      출장지 검색 + 구분선 + 등록 목록
3 방문순서를 추천받으세요   준비 체크리스트 · 복귀 토글 · 주요 버튼
결과        순서도 → 총거리 → 복사·인쇄 → (접힘) 구간표 → 주의
푸터
토스트      화면 하단 중앙, 항상 1개만
```

### 배치 원칙

- **카드 3개를 넘기지 않습니다.** 설정과 결과는 조건부로만 나타납니다.
- 섹션 제목은 **질문형**입니다("어디에서 출발하나요?"). 사용자가 할 일을 바로 알립니다.
- 결과에서는 **추천 순서가 총거리보다 먼저** 옵니다. 읽는 순서가 곧 중요도입니다.
- **복사·인쇄는 구간 표보다 먼저** 둡니다. 표를 지나쳐 찾게 만들지 않습니다.
- 자주 쓰지 않는 것은 접습니다 — 구간 표, 좌표, 키 보안 설명, 직선거리 상세.

## 2. 색상과 타이포그래피

모든 값은 `:root` 의 CSS 변수로만 정의합니다. 값을 직접 적지 마세요.

### 색상

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg` | `#f4f5f7` | 페이지 배경 |
| `--surface` | `#fff` | 카드·입력 |
| `--surface-2` | `#fafbfc` | 보조 영역, 표 머리 |
| `--line` / `--line-strong` | `#e6e9ee` / `#d4d9e0` | 경계선 |
| `--ink` / `--ink-2` / `--ink-3` | `#16191f` / `#5a6372` / `#8b93a1` | 본문 / 보조 / 흐림 |
| `--accent` / `--accent-ink` | `#1b64da` / `#164fb0` | 주요 버튼, 링크 |
| `--accent-wash` / `--accent-line` | `#eef4ff` / `#c8dcfb` | 강조 배경 |
| `--ok` · `--warn` · `--err` | `#0d7c4a` · `#8f5e07` · `#be3029` | 상태 (각각 `-wash`, `-line` 짝) |

강조색은 **파란색 하나**입니다. 초록·노랑·빨강은 상태 표시에만 씁니다.
장식용 그라데이션, 의미 없는 아이콘은 쓰지 않습니다.

### 타이포그래피

| 역할 | 크기 / 굵기 |
|---|---|
| `h1` 프로그램명 | 23px / 700 |
| `h2` 섹션 제목 | 17.5px / 700 |
| `h3` 소제목 | 14.5px / 700 |
| 본문 | 15.5px / 400, 줄간격 1.65 |
| `.sub` 보조 | 13.5px |
| `.tiny` 부가 | 12.5px |
| 총거리 강조 | 32px / 700 |

- 글꼴: Pretendard → Apple SD Gothic Neo → 맑은 고딕 순으로 내려갑니다. **웹폰트를 내려받지 않습니다.**
- 한국어 줄바꿈은 `word-break:keep-all` 로 단어 단위를 지킵니다.
- 긴 장소명·도로명주소는 `overflow-wrap:anywhere` 로 넘치지 않게 합니다.

### 간격과 모서리

- 카드 안쪽 여백 22/24px(모바일 18/16px), 카드 사이 14px
- 모서리: 카드 14px, 입력·버튼 10px, 칩 999px
- 터치 영역 **최소 44px** (`--tap`). 보조 버튼(`.sm`)만 36px를 허용합니다.

## 3. 공통 요소

### 버튼

| 종류 | 클래스 | 쓰는 곳 |
|---|---|---|
| 주요 | `.primary` | 검색, 선택, 복사 |
| 최상위 행동 | `.primary.cta` | **최적 방문순서 추천** — 화면에 하나뿐 |
| 기본 | (없음) | 인쇄, 변경, 보기 |
| 약한 | `.quiet` | 전체 삭제, 좌표 표시, 닫기 |
| 위험 | `.danger` | 저장된 키 삭제 |
| 작게 | `.sm` | 목록·결과 안의 보조 버튼 |

`.cta` 는 **한 화면에 하나만** 둡니다. 다른 버튼과 경쟁시키지 마세요.

### 입력

- 모든 입력에 `<label>` 또는 `aria-label` 을 붙입니다. 시각적으로 숨길 때는 `.sr-only`.
- 검색창은 Enter 키로도 실행됩니다.
- 포커스는 `:focus-visible` 로 2.5px 윤곽선을 그립니다. 절대 없애지 마세요.

### 상태 칩 (`.chip`)

색만으로 구분하지 않고 **반드시 문구를 함께** 넣습니다.

| 위치 | 값 |
|---|---|
| 헤더 (SDK) | 검색 준비됨 / 키 설정 필요 / 연결 중 / 연결 오류 / 로컬 실행 |
| 출발지 | 미확정 / 확정 |
| 출장지 | `0곳 등록` / `3곳 등록 · 5곳 더 가능` / `8곳 등록 · 최대` |

숫자만 쓰지 않습니다(`0 / 8` ✗). 다만 8곳 제한 자체는 반드시 유지합니다.

### 안내 상자 (`.note`)

`info` / `ok` / `warn` / `err` 네 가지. **정상일 때는 비워 둡니다** (`.note:empty` 는 사라짐).
해결 행동이 있으면 상자 안에 버튼을 넣습니다(예: "설정 열기").

### 토스트

- 짧은 **성공** 피드백에만: 등록, 삭제, 복사, 키 저장.
- **항상 1개만** 유지합니다. 새 토스트가 이전 것을 대체합니다.
- 2.6초 후 사라집니다.
- **오류에는 쓰지 않습니다.** 오류는 화면에 남아야 합니다.

### 준비 체크리스트 (`.ready`)

추천 버튼 위에서 남은 할 일을 보여 줍니다.
버튼을 비활성화하는 대신, 눌렀을 때 **무엇을 먼저 해야 하는지** 알리고 그 입력으로 이동시킵니다.

## 4. 모바일 대응

기준 폭: **375 / 390 / 430 / 768 / 1280px**. 전부 가로 스크롤이 없어야 합니다.

- 분기점은 `640px` 하나입니다. 그 아래에서 여백을 줄이고 검색 결과의 선택 버튼을 전폭으로 바꿉니다.
- **구간 표는 640px 아래에서 세로 카드로 바뀝니다.**
  `thead` 를 숨기고 각 `td` 가 `data-label` 을 제목으로 표시합니다.
  표를 그대로 두면 셀이 한 글자씩 쪼개집니다. 새 열을 추가하면 `data-label` 도 반드시 추가하세요.
- 고정(fixed) 요소는 토스트뿐입니다. 하단 고정 버튼 바를 만들지 마세요 —
  모바일 키보드와 검색 결과를 가립니다.

## 5. 사용자 행동 흐름

```
(키 없음)  헤더 칩 "키 설정 필요" → 안내 상자의 [설정 열기] → 키 입력 → 적용
    ↓
1 출발지   기본 검색어 "충주시청" → 검색 → 결과에서 선택 → 칩이 "확정"으로
    ↓
2 출장지   검색 → 결과에서 선택 → 토스트 "추가됨" → 목록에 쌓임 (최대 8)
    ↓
3 추천     체크리스트 ✓✓ 확인 → 복귀 여부 → [최적 방문순서 추천]
    ↓
결과       순서도 → 총거리 → 복사/인쇄 → (필요하면) 구간 표 펼치기
```

**막혔을 때의 대안 경로**: 검색이 실패하면 "위도·경도 직접 입력"이 자동으로 펼쳐집니다.
이 경로만으로도 추천·복사·인쇄가 모두 동작해야 합니다.

### 상태가 바뀌면 결과를 버립니다

출발지·출장지·복귀 여부가 바뀌면 이전 결과를 숨깁니다(`invalidateResult`).
낡은 결과를 화면에 남겨 두지 마세요.

## 6. 앞으로 디자인을 고칠 때 지킬 기준

1. **단일 HTML 유지.** CSS·JS를 별도 파일로 분리하지 않습니다.
2. **토큰으로만 색을 씁니다.** `:root` 밖에 색상 리터럴을 적지 않습니다.
3. **설명을 늘리지 않습니다.** 문구를 추가하기 전에, 접을 수 있는지 먼저 보세요.
4. **색만으로 뜻을 전하지 않습니다.** 상태에는 항상 문구를 같이 둡니다.
5. **`.cta` 는 하나.** 주요 행동을 늘리지 마세요.
6. **접근성 회귀 금지.** 라벨, 포커스 윤곽선, 44px 터치 영역, `aria-live`,
   Esc 닫기, `prefers-reduced-motion` 은 `tests/verify.mjs` 가 검사합니다.
7. **반응형 회귀 금지.** 표에 열을 더하면 `data-label` 도 더합니다.
   다섯 가지 기준 폭에서 가로 스크롤이 생기면 안 됩니다.
8. **인쇄 화면 확인.** 입력·버튼은 빠지고 결과만 나와야 하며,
   접힌 구간 표는 인쇄 시 펼쳐져야 합니다.
9. **애니메이션은 최소.** 토스트 등장 외에는 쓰지 않습니다.
10. **대시보드·차트를 만들지 않습니다.** 이 도구는 숫자 하나와 순서 하나를 보여 주면 됩니다.
